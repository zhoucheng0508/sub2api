# 首字监控发布说明

本次从 `custom-v0.2.15-2`（`8d92386c8`）准备首字监控功能发布，候选标签 `custom-v0.2.15-3`。只包含首字监控、恢复保护、OAuth 原因校验与调度快照版本保护，保留最新 custom 已有功能；不引入旧工作区尚未提交的视频、余额或 Codex 修改。

## 迁移

最新主线已有迁移 240–242，本功能发布时使用：

- `243_first_token_monitor_generation.sql`：数据库管理监控配置/恢复代次。
- `244_account_scheduler_state_version.sql`：独立账户行版本，每次 INSERT/UPDATE 推进，暂停建立/延长/解除均覆盖；Redis writer 拒绝旧快照。

旧的本地交接和 0.2.4 预览使用 240/241，不能按旧序号在生产执行。生产由新镜像自动执行 243/244；不要修改已应用迁移。监控默认关闭，不自动开启任何账户。

## 已执行本地验证

- 后端监控/使用记录、恢复、TokenRefresh、调度快照相关定向测试通过。
- 本地真实 PostgreSQL 18、Redis 集成测试通过：隔离 schema 执行 243/244，包含 session 终止恢复、凭证条件清理、版本推进与防伪、暂停前快照迟到和双客户端写入。测试 schema/键已清理。
- 前端创建/编辑、组件、composable、locale 共 5 文件 111 项测试通过；ESLint、类型检查及全新生产构建通过。
- 远端集成测试发现调度版本影响原有 credentials 全量比较，已将数据库管理的 scheduler_state_version 排除于凭证身份比较；保留真实密钥、Token、监控配置校验。原失败 PostgreSQL 用例与新增普通更新/实际 Token 更换回归通过。
- 路由和 server 编译检查通过；golangci-lint 对相对 origin/custom 的变更检查通过。

远端 PR：[首字监控 #36](https://github.com/zhoucheng0508/sub2api/pull/36)。必须等待 PR/custom CI 与安全扫描通过，再按 `CUSTOM_UPGRADE.md` 创建标签，由 `custom-image.yml` 构建 Linux amd64 镜像。正式部署使用核实后的 GHCR 镜像摘要，不使用挂载二进制预览代替正式镜像。

## 已接受的限制

监控在完成请求的使用记录阶段评估，滚动窗口按处理时间计算。暂停以数据库/outbox 为依据，传播有延迟，默认 1 秒轮询并非生效时间上限。跨数据库/Redis 非事务、无后续请求时的暂停补偿、多完整实例故障收敛、负载和回滚尚未充分验证。项目负责人已接受这些已知限制，不再作为合入阻塞项；不能据此认定生产稳定性已验证。

## 生产切换前

用户要求：**正式部署前先报告待部署版本及检查结果，收到确认后才开始部署。** Git 提交、PR、标签、镜像构建和备份准备不等于生产部署授权。

1. 核实当前生产镜像摘要、实际 Compose 文件组合、Linux amd64、空间、应用/PostgreSQL/Redis 健康。
2. 数据库 custom dump、globals、应用数据/Compose/.env 和 Redis RDB 备份置于服务器 root-only 目录，生成 SHA-256；`pg_restore --list` 和临时库实际恢复并核对关键表。不得输出凭证或将备份提交 Git。
3. 验证目标正式镜像、内嵌提交/版本和本地隔离健康启动，记录摘要。
4. 获得用户明确确认后，仅更新应用服务，保留 PostgreSQL/Redis、数据卷和生产配置。避免旧 writer 与新 writer 混跑。
5. 核实运行镜像 ID、公网/本机健康、迁移 243/244、错误日志及账户监控开关显示；默认不自动开启真实账户监控。

## 回退

保留旧生产摘要、Compose 配置和已恢复验证的备份。数据库迁移单向，旧二进制不会遵守新屏障；不能把“换回旧镜像”视为已验证安全回滚，不删除屏障键或数据卷。发生故障先停止新请求并评估数据库/缓存兼容性，禁止用旧 dump 直接覆盖升级后的账单与使用数据。
